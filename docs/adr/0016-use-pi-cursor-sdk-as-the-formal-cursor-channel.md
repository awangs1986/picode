# Use pi-cursor-sdk as Picode's formal Cursor channel

Picode uses `fitchmultz/pi-cursor-sdk` pinned to `npm:pi-cursor-sdk@0.1.61` as its only executable Cursor provider. The package preserves Cursor's official `@cursor/sdk` local Agent loop while exposing Pi-native authentication, model discovery, sessions, and replay events. Its local resume store is isolated by Pi Chat Session, restores only when session/workspace/model/tool/store/compaction identity matches exactly, and bootstraps a new Cursor Agent from the current Pi transcript when strict restoration fails.

Picode owns a separate Pi Runtime Profile under its application data directory. Package settings, `auth.json`, provider definitions, SDK state, and installed executable extensions no longer share standalone Pi's `~/.pi/agent` directory. `PI_CODING_AGENT_SESSION_DIR` still points at the existing standalone Pi session tree, so GUI and TUI preserve the user's chats. A one-time migration copies non-secret settings and package declarations into the Picode profile but removes every Cursor provider package before installing the pinned formal SDK; source settings and credentials are never modified or copied.

Cursor Desktop/CLI OAuth remains manually importable only as an encrypted backup record. Existing OAuth records are retained but deactivated, new imports are not chat-compatible, and the unofficial `@rahularya01/pi-cursor` package is rejected by Picode's package boundary. Automatic Cursor credential discovery stays disabled. A manually supplied Cursor SDK API key and Node.js 22.19 or later are required for Cursor chat.
