## Security and resource decisions

- Resident core: chat/task control, authorization, filesystem read/write, process execution, secrets, and runtime registry only.
- Installed Global and Task Extensions contribute catalog metadata, not a resident process. Loading requires a task decision and the unified authorization surface.
- Extension permission expansion requires review. A failed migration retains the prior configuration.
- Tools, logs, evidence, DAP events, runtime samples, and live process tails have hard retention limits. Full artifacts are content addressed outside prompt context.
- Secret values are resolved just in time. Configurations and checkpoints store only references.
- Hash/content anchors are optional model aids and never bypass the underlying stale-file version check.
- Low CPU is not a stall signal. Known model/tool/user/permission waits suppress false stall classification; suspected stalls never auto-terminate.

## Rejected approaches

- Embedding OMP or OpenCode as another agent core: duplicates Pi, adds memory, and contradicts Picode’s lightweight goal.
- Starting all LSP/MCP/extensions at application launch: unbounded idle cost and changes Simple Task semantics.
- Importing proprietary Claude/Cursor implementation code: not license-safe. Only documented external formats and observable behavior may be supported.
- Ranking Subagent models primarily by price: quality, task-class evaluation, context/tool compatibility, and provider health precede cost.

## Notice and copying record

No third-party source code was copied in this implementation. The cited projects informed behavior and interface boundaries; the Rust modules and browser components are clean-room Picode code. Existing repository notices remain applicable to pre-existing dependencies.
